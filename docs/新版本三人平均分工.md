> 原则：不按“前端/后端/算法”机械拆分，而按能独立展示的业务闭环平均分配；每个人都覆盖前端、后端、安全、测试、报告。

## 3. 组员 A：基础考勤与活体交互闭环（33%）

### 3.1 前端任务

| 任务 | 文件/页面 | 内容 |
|---|---|---|
| 摄像头调用 | `static/js/app.js::startCamera()` | `getUserMedia()` 打开摄像头，失败提示权限/localhost |
| 手动抓拍预检 | `manualCaptureBtn` | 调 `/api/attendance/preview`，显示质量、候选、情绪，不写考勤 |
| 正式活体打卡 | `startCheckBtn` | 获取 challenge，按 3 组随机挑战采帧 |
| 单组采帧 | `captureStageUntilPass()` | 每组最多 5 秒，后端判通过才进入下一组 |
| 高帧率眨眼 | `captureIntervalMs` | blink 约 70ms，flash 约 120ms，其他约 140ms |
| 随机闪光显示 | `setFlashColor()`、`captureFrame()` | 屏幕闪光，并把边缘颜色水印写入采集帧 |
| 状态展示 | `challengeSteps`、`attendanceMsg` | 当前组、动作、闪光色、采帧数、后端原因 |
| 结果渲染 | 考勤结果框 | 姓名、学号、时间、活体分、人脸分、阈值、情绪 |
| 查询交互 | 考勤记录页 | 学号、日期筛选 |

### 3.2 后端任务

| 任务 | 接口 | 当前行为 |
|---|---|---|
| 生成 challenge | `/api/attendance/challenge` | 清掉旧 challenge；随机 3 组；保证至少 1 组 `flash_response`；90 秒过期 |
| 单组检测 | `/api/attendance/liveness-stage` | 校验 challenge、stage、帧数、时限；调用 `analyze_liveness()`；返回 `stage_pass` |
| 正式考勤 | `/api/attendance/check` | 全部帧重新活体检测，再识别、情绪、入库 |
| 手动预检 | `/api/attendance/preview` | 单帧质量/候选/情绪，不写考勤 |
| 记录查询 | `/api/attendance` | 学号/日期筛选，学生只能查本人 |

### 3.3 安全与测试

- 保证手动预检不能绕过活体。
- 保证第二次开始活体会重置旧 challenge。
- 测试摄像头失败、挑战过期、帧数不足、无人脸、不按动作、正常打卡。
- 配合组员 C 解释前端不可信、最终由后端复核。

### 3.4 报告和答辩

负责基础考勤流程、摄像头采集、手动/自动捕捉、异常处理、考勤记录查询。核心话术：

> 我负责考勤闭环。手动抓拍只做预检不写考勤；正式打卡由后端生成三组随机挑战，每组五秒内完成，当前组通过才进入下一组，最终后端重新检查所有帧，再做人脸匹配和情绪分析。

### 4.3 安全与测试

- 教师接口必须 `require_role("teacher")`。
- 学生查询考勤、活动、情绪都按当前 `student_id` 过滤。
- `/storage` 防路径穿越，学生不能看他人文件。
- 批量导入失败必须出现在失败清单。
- 测试教师登录、学生登录、越权 403、样本预览、样本删除、Excel 导出。

### 4.4 报告和答辩

负责架构、数据库、接口、权限、人脸库管理、部署说明、隐私说明。核心话术：

> 我负责数据和人脸库底座。系统把学生、账号、样本、考勤、情绪、活动参与和审计拆表管理；权限在后端强校验。人脸库支持严格命名批量导入，导入后弹成功/失败清单，样本可预览和单独删除。Excel 和 storage 文件访问也按角色控制。

### 5.1 前端任务

| 任务 | 页面 | 内容 |
|---|---|---|
| 合照上传 | 合照识别 | 上传图片并显示结果 |
| 逐脸表格 | 合照识别 | 自动确认/候选、分数、样本数、情绪引擎 |
| 标注图 | 合照识别 | 展示 `annotated_url` |
| 人工确认 | 合照识别 | 自动结果 + 候选 + 补选最终名单 |
| 活动统计 | 统计报表 | 参与频次柱状图 |
| 情绪统计 | 统计报表 | scene/emotion 分布 |
| 安全自测 | 安全自测 | 静态、样本、移动照片、预录视频、随机性展示 |
| 情绪诊断 | 验收清单 | 显示 EmotiEffLib 模型状态 |

### 5.2 后端与算法任务

| 任务 | 函数/接口 | 内容 |
|---|---|---|
| 人脸检测 | `detect_faces()` | Haar 正脸/侧脸、NMS、质量排序 |
| 特征提取 | `face_embedding()` | LBP + HOG + DCT + 低频结构 |
| 人脸识别 | `recognize()` | 学生级多样本聚合，阈值和分差 |
| 活体检测 | `analyze_liveness()` | 10 动作、3 组、时序、质量、重复帧、刚性平面、屏幕/打印、随机打光 |
| 闪光检测 | `_flash_response_check()` | 人脸 RGB/亮度/色度与 session 随机序列相关性 |
| 合照识别 | `/api/group/recognize` | 检测、识别、情绪、标注、入库 |
| 活动确认 | `/api/group/<id>/participants` | 教师确认/补选参与名单 |
| 情绪分析 | `analyze_emotion()` | EmotiEffLib → DeepFace → 启发式，surprise 稳定化 |
| 情绪诊断 | `/api/emotion/diagnostics` | 模型可用性和错误信息 |
| 安全自测 | `/api/liveness/self-test*` | 静态重复帧、移动照片、预录视频无闪光响应 |
| 随机展示 | `/api/security/challenge-randomness` | 10P3=720、4 段闪光、90 秒过期 |

### 5.3 安全与测试

- 解释每个动作：`cx/cy/area/eye/mouth/yaw/flash`。
- 解释照片攻击：重复帧、平均帧差、归一化 crop、平面纹理/高光/摩尔纹。
- 解释视频攻击：随机动作、5 秒逐组 gating、90 秒过期、随机打光。
- 测试 `liveness_stage_selftest.py`、`liveness_antispoof_selftest.py`、`group_collage_selftest.py`、`group_collage_50_selftest.py`、`emotion_selftest.py`。

### 5.4 报告和答辩

负责算法设计、活体检测细节、抗伪造实现、合照准确率、情绪模型、结果分析和局限改进。核心话术：

> 我负责算法和安全评测。人脸识别用本地 LBP/HOG/DCT 特征并按学生聚合多样本；活体用三组随机原子动作，结合人脸中心、面积、眼口、转头、质量、重复帧、平面伪造和随机打光响应；合照会生成标注图和参与名单；情绪优先 EmotiEffLib ONNX，并对低置信 surprise 做稳定化。
