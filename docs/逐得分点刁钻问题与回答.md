## 0. 当前系统事实

| 项目 | 当前实际实现 |
|---|---|
| BS 架构 | Flask 后端 + 原生 HTML/CSS/JS 前端 + SQLite 数据库 |
| UI | `Rhodes Tactical Terminal · Content Security Lab` 战术终端风格 |
| 活体动作池 | `move_left`、`move_right`、`move_closer`、`move_away`、`nod`、`blink`、`open_mouth`、`turn_left`、`turn_right`、`flash_response`，共 10 种；已删除向上/向下移动 |
| 活体流程 | 每次 3 组，每组 1 个动作，每组最多 5 秒；整次 challenge 90 秒过期；点击第二次开始会覆盖旧 challenge |
| 随机闪光 | 每组 4 段随机颜色，700ms 切换；正式挑战保证至少 1 组 `flash_response` |

| 人脸匹配 | 考勤/预检阈值 `0.70`，0.708 可匹配最相近学生；同时显示第二名分数、分差、最佳单样本分和样本数 |

## 1. 架构要求（10 分）

### Q1：为什么说这是 BS 架构，不是普通本地程序？
**答：组员 B。** BS 指 Browser/Server 职责分离，不要求服务端必须部署公网。当前浏览器只负责摄像头、上传、交互和渲染；Flask 后端负责 API、权限、算法和数据库；二者通过 HTTP JSON API 通信，所以是 BS 架构。

### Q2：前端、后端、数据库、算法分别在哪？
**答：组员 B。** 前端是 `templates/index.html`、`static/css/app.css`、`static/js/app.js`；后端路由是 `app.py`；数据库初始化在 `core/db.py`；权限在 `core/security.py`；视觉算法在 `core/vision.py`。

### Q3：前端 JS 被改能不能伪造通过？
**答：组员 A。** 不能。前端只是采帧和展示，后端 session 保存 challenge id、动作序列和闪光序列；`/api/attendance/liveness-stage` 和 `/api/attendance/check` 都会重新调用 `analyze_liveness()`，前端不能自己决定通过。

### Q4：接口规范在哪里体现？
**答：组员 B。** 普通接口统一 `/api/*`，成功返回 `ok:true`，失败返回 `ok:false/error`；文件下载接口单独返回文件流，如 `/api/attendance/export` 导出 xlsx。

### Q5：数据库为什么拆这么多表？
**答：组员 B。** 学生、用户、人脸样本、考勤、情绪、活动、参与关系、审计日志分别承担不同职责，避免冗余，也方便按学生、场景、活动聚合统计。

## 2. 基础考勤（25 分）

### Q1：摄像头怎么调用？
**答：组员 A。** 前端 `startCamera()` 用 `navigator.mediaDevices.getUserMedia()` 打开实时视频流，理想分辨率 960×720、理想帧率 30、最大 60，绑定到 `<video id="video">`。失败会提示检查浏览器权限和 localhost/HTTPS。

### Q2：手动抓拍和正式打卡有什么区别？
**答：组员 A。** 手动抓拍调用 `/api/attendance/preview`，只返回人脸数、质量、候选学生、匹配分和情绪，不写入 `attendance_records`。正式打卡必须先获取 `/api/attendance/challenge`，再按 3 组随机动作采多帧，最后 `/api/attendance/check` 写入考勤。

### Q3：自动采帧怎么实现？
**答：组员 A。** `captureStageUntilPass()` 每组最多采 5 秒。眨眼组约 70ms 一帧，随机打光约 120ms，其他动作约 140ms。达到最少帧数后周期性请求 `/api/attendance/liveness-stage`，当前组通过才进入下一组。

### Q4：第二次点击“开始活体打卡”会不会叠加旧任务？
**答：组员 A。** 不会。`/api/attendance/challenge` 里先 `session.pop("attendance_challenge", None)`，旧 challenge 会被清掉，然后生成新的 challenge，相当于重新开始。

### Q5：考勤结果返回哪些字段？
**答：组员 A。** 状态、姓名、学号、时间、活体通过情况和分数、人脸匹配分、匹配阈值、最佳单样本分、样本数、情绪和备注。

### Q6：识别失败是否入库？为什么？
**答：组员 B。** 会入库。失败记录用于安全审计，例如活体失败、人脸未匹配、学生账号试图替别人打卡等。

### Q7：考勤记录筛选在哪里做？
**答：组员 B。** 后端 `/api/attendance` 根据学号、开始日期、结束日期拼接 SQL 条件；学生账号会强制追加 `student_id = 当前学生`，最多返回 300 条。

### Q8：Excel 导出怎么做？
**答：组员 B。** `/api/attendance/export` 用 `openpyxl` 生成 `attendance_records.xlsx`，教师导出全部，学生只导出本人。

## 3. 活体检测：每个挑战怎么检测

### Q1：活体有哪些挑战？
**答：组员 A。** 当前动作池 10 个：向左、向右、靠近、远离、点头、眨眼、张嘴、左转头、右转头、随机打光。每次随机抽 3 组，每组只做 1 个动作；向上和向下移动已经删掉。

### Q2：向左/向右怎么判断？
**答：组员 C。** 后端按时间排序一组帧，比较早期和后期人脸中心 `cx`。向左要求 `last_cx - first_cx` 为负且超过阈值，或相对基准中心明显偏左；向右相反。

### Q3：靠近/远离怎么判断？
**答：组员 C。** 比较人脸框面积 `area` 的前后比例。靠近时后期面积变大，远离时后期面积变小，也参考基准阶段平均面积。

### Q4：点头怎么判断？
**答：组员 C。** 看人脸中心 `cy` 的变化范围 `y_range` 或净位移 `dy`，超过阈值说明有点头式垂直运动。

### Q5：眨眼怎么判断？
**答：组员 C。** 前端提高眨眼采样频率；后端融合 `eye_dark_range`、`eye_dark_delta`、`closed_eye_proxy` 和短时人脸可见率，判断是否出现闭眼峰值。

### Q6：张嘴怎么判断？
**答：组员 C。** 后端在嘴部区域计算 `mouth_open`、`mouth_dark`、`mouth_edge` 和黑色开口区域，嘴部开合增量或范围超过阈值即通过。

### Q7：左右转头怎么判断？
**答：组员 C。** 用 `yaw_proxy` 表示左右半脸结构/亮度差异，同时看 `face_aspect` 和中心横向位移。向左/向右要求 yaw 方向变化或 yaw 范围达到阈值。

### Q8：随机打光怎么判断？
**答：组员 C。** 后端 session 保存每组 4 段随机颜色序列。前端显示闪光并提交 flash index/rgb，后端用 session 重新计算 expected rgb，再比较人脸区域 RGB、亮度、色度变化是否和随机序列同步，同时检查前端元数据是否一致。

### Q9：单组怎么判完成？
**答：组员 A。** `/api/attendance/liveness-stage` 校验 challenge、stage、帧数和时限后调用 `analyze_liveness(frames, [action])`。`motion_checks[0].ok` 且有效人脸帧不少于 3，就返回 `stage_pass=true`。

### Q10：最终活体怎么判通过？
**答：组员 C。** 正式 `/api/attendance/check` 会重新检查全部帧，要求三组动作都过、质量达标、不是重复静态帧、没有刚性平面/屏幕打印风险、闪光元数据一致、单组不超时，并且综合分 `>=0.70`。

## 4. 图片伪造和视频伪造防护

### Q1：静态照片为什么过不了？
**答：组员 C。** 静态照片复制成多帧时，感知哈希唯一比例低、平均帧差低、动作变化不足，触发 `static_replay`，返回“检测到重复静态帧，疑似照片/重放攻击”。安全自测页可现场运行静态照片/无摄像头样本攻击。

### Q2：举着照片移动为什么过不了？
**答：组员 C。** 举照片会让整帧或人脸框位置变化，但归一化后的人脸 crop 几乎刚性不变。系统计算 `avg_crop_diff`、`crop_unique_ratio`、`motion_extent`，触发 `rigid_planar_replay` 后拒绝。

### Q3：手机屏幕或打印件怎么识别？
**答：组员 C。** `_crop_signal_features()` 提取 `specular_ratio`、`fft_high_ratio`、`moire_score` 等指标。屏幕/打印件常有异常高光、摩尔纹和高频网格风险，触发 `screen_or_print_risk`。

### Q4：预录视频为什么不能通过？
**答：组员 C。** challenge 是本次 session 实时随机生成：10 个动作中抽 3 组，有序组合 10P3=720；每组最多 5 秒，整次 90 秒过期；并且至少一组是随机打光。预录视频不知道本次动作顺序，也无法让视频里的人脸颜色按本次随机颜色变化。

### Q5：预录视频攻击自测具体构造了什么？
**答：组员 C。** `/api/liveness/self-test-prerecorded` 构造动作看起来正确、且提交正确 flash 元数据的帧，但画面本身不响应随机颜色，模拟提前录好的视频。后端会因人脸区域没有本次随机闪光响应而拒绝。

### Q6：随机打光识别弱，为什么 0.70 能过？
**答：组员 C。** 普通摄像头自动白平衡会压缩屏幕打光。当前实现允许“弱打光”作为 warning，只要综合分 `>=0.70` 且动作、质量、时序、反伪造硬指标都通过，可以避免误拒；但如果闪光元数据不一致、重复帧、刚性照片、屏幕/打印风险触发，仍然拒绝。

### Q7：这是不是金融级活体？
**答：组员 C。** 不是金融级，但已覆盖课程要求的照片、移动照片、预录视频伪造防护。后续可替换/叠加深度活体模型、随机读数字或深度摄像头。

## 5. 人脸库与识别

### Q1：批量导入文件名格式？
**答：组员 B。** 仅支持 `学号-姓名-专业-性别.jpg/png`，例如 `2022302181209-吴悦-网络空间安全-女.jpg`。`学号-姓名=专业-性别` 当前不支持。

### Q2：导入后怎么知道哪些成功失败？
**答：组员 B。** `/api/students/faces/bulk` 返回 added/errors，前端会弹“批量导入结果”模态框，列出新增学生、更新学生、新增样本、成功清单和失败清单。

### Q3：一个学生多张照片如何提高准确率？
**答：组员 C。** `recognize()` 按学生聚合多样本分数，融合最佳单样本、TopK 均值、质量加权质心、支持样本数。多角度、多光照高质量样本越多，识别越稳；低质量离群样本只弱参与，且可在样本面板删除。

### Q4：样本图片能预览吗？
**答：组员 B。** 能。`/api/students/<id>/faces` 返回样本 URL，前端“样本”按钮展示图片、质量分、创建时间和删除按钮。学生只能查看自己的样本。

## 6. 合照识别（9 分）

### Q1：合照识别流程？
**答：组员 C。** 教师上传合照到 `/api/group/recognize`，后端保存原图，检测多人脸，逐脸提取 embedding，调用 `recognize()` 匹配人脸库，同步 `analyze_emotion()`，生成标注图并写入活动、参与和情绪表。

### Q2：怎么证明 85% 准确率和 10-50 人？
**答：组员 C。** `docs/group_collage_selftest_report.json`：10 人合照检测 10、匹配 10、recall=1.0、precision=1.0；`docs/group_collage_50_selftest_report.json`：50 人压力图检测 50、匹配 50、recall=1.0、precision=1.0。

### Q3：真实复杂合照也能 100% 吗？
**答：组员 C。** 不承诺所有真实复杂场景 100%。Haar 和轻量特征对遮挡、低清晰度、极端侧脸有限，所以系统保留教师确认/补选，防止低置信自动误写。

### Q4：活动频次怎么统计？
**答：组员 B。** 每次合照生成 `activities`，确认参与学生写入 `activity_participants`。`/api/group/stats` 按学生聚合 `COUNT(*)`，前端柱状图展示。

## 7. 情绪分析（8 分）

### Q1：情绪检测怎么实现？
**答：组员 C。** 对人脸 crop 先计算启发式特征：嘴部开合、嘴部暗区、眼部闭合线、亮度、对称性；再优先调用 EmotiEffLib ONNX `enet_b0_8_best_vgaf`，输入前 BGR 转 RGB；不可用则回退 DeepFace，再回退启发式。

### Q2：怎么证明用的是当前模型？
**答：组员 C。** `/api/emotion/diagnostics` 和验收清单页显示 `available`、`model_name`、`model_engine`、`recognizer_ready`、`model_error`，可现场证明当前实际 engine。

### Q3：为什么不会总是 surprise？
**答：组员 C。** `_stabilize_emotion()` 对低置信 `surprise` 做保护：如果嘴部开合和纵向跨度不支持惊讶，就改成 neutral、启发式结果或第二候选，并保留原始 `model_emotion/model_confidence` 给前端显示。

### Q4：情绪数据怎么统计？
**答：组员 B。** `emotion_records` 保存学号、姓名、情绪、置信度、场景、图片路径和时间。`/api/emotions/stats` 按 `emotion/scene` 聚合，学生账号只看本人。

## 8. 权限与异常防护

### Q1：教师和学生权限怎么做？
**答：组员 B。** `users.role` 区分 teacher/student。前端隐藏教师标签；后端教师接口使用 `require_role("teacher")`。学生查询考勤、活动、情绪时都强制按当前 `student_id` 过滤。

### Q2：学生能不能猜 `/storage` 路径看别人照片？
**答：组员 B。** 不能。`/storage/<path>` 需要登录，学生只能访问数据库中属于自己的 `face_samples.image_path`，其他文件返回 403。

### Q3：上传失败怎么办？
**答：组员 B。** 批量导入和单样本上传都会逐项返回错误，例如文件名格式错、图片解析失败、未检测到清晰人脸；前端弹窗展示失败清单。
