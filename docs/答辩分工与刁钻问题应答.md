## 1. 当前系统已实现内容

- **前端**：`templates/index.html`、`static/css/app.css`、`static/js/app.js`，原生 HTML/CSS/JS，明日方舟式战术终端 UI。
- **后端**：`app.py`，Flask 提供 `/api/*` JSON 接口。
- **数据库**：`core/db.py`，SQLite，含学生、用户、人脸样本、考勤、情绪、活动参与、审计等表。
- **权限**：`core/security.py`，`require_login()`、`require_role()`，教师/学生分权，storage 访问也限权。
- **人脸库**：支持单学生多图上传、摄像头补采、样本预览/删除、严格命名批量导入、导入成功/失败清单。
- **人脸识别**：`core/vision.py::face_embedding()` 使用 LBP + HOG + DCT + 低频结构；`recognize()` 按学生聚合多样本分数。
- **活体检测**：10 种原子动作池，3 组随机挑战，每组最多 5 秒，综合分阈值 0.70，照片/移动照片/预录视频专项自测。
- **随机打光**：每组 4 段随机颜色，700ms 切换；后端校验人脸颜色/亮度/色度响应和 session 序列一致性。
- **合照识别**：上传合照后批量检测、识别、情绪分析、标注图、活动频次入库，支持教师确认/补选。
- **情绪分析**：优先 EmotiEffLib ONNX `enet_b0_8_best_vgaf`，回退 DeepFace/启发式；低置信 surprise 稳定化。
- **导出与报告**：考勤 Excel、验收清单 Markdown、合照 10/50 人自测报告、final acceptance 报告。

## 4. 老师高频刁钻问题与当前系统回答

### 4.1 活体检测

**Q：每个挑战如何检测？**  
A：每组帧按时间排序，比较早期和后期人脸特征。左右移动看 `cx`，靠近远离看人脸面积 `area`，点头看 `cy/y_range`，眨眼看 `eye_dark/closed_eye_proxy`，张嘴看 `mouth_open/mouth_dark/mouth_edge`，转头看 `yaw_proxy/face_aspect`，随机打光看人脸 RGB/亮度/色度是否和后端 session 随机序列同步。

**Q：怎么判断挑战完成？**  
A：单组 `/api/attendance/liveness-stage` 要求 challenge 有效、帧数足够、未超时、该动作 `motion_checks[0].ok`。正式打卡 `/api/attendance/check` 还会重新检查全部帧，要求 3 组动作、质量、时序、反伪造、闪光元数据和综合分都达标。

**Q：为什么 0.70 就能过？**  
A：0.70 是综合活体最低分和人脸匹配阈值，但不是单独条件。活体还要求动作、质量、时序、反伪造硬指标；人脸识别还展示第二名分数、分差、最佳单样本和样本数，合照还有教师确认。

### 4.2 图片伪造

**Q：举着照片移动也有动作，为什么不能通过？**  
A：系统不仅看人脸框位置，还看归一化人脸内部变化。移动照片的整帧在动，但归一化人脸 crop 几乎刚性不变，`avg_crop_diff` 小、`crop_unique_ratio` 低，会触发 `rigid_planar_replay`。静态照片还会触发重复帧和低帧差。

**Q：打印件或手机屏幕呢？**  
A：系统提取 `specular_ratio`、`moire_score`、`fft_high_ratio` 等屏幕/打印风险特征；同时随机打光要求人脸区域对本次颜色序列有真实响应。

### 4.3 视频伪造

**Q：提前录制一段眨眼张嘴视频能不能过？**  
A：难。正式挑战本次 session 随机 3 组动作，每组 5 秒逐组 gating，整次 90 秒过期，并保证至少 1 组随机打光。预录视频不知道本次动作顺序，也无法让视频里的人脸颜色按本次随机颜色同步变化。

**Q：随机打光识别弱怎么办？**  
A：普通摄像头自动白平衡会压缩打光，所以系统允许弱打光 warning 时按综合分通过；但闪光元数据不一致、重复帧、刚性平面、屏幕/打印风险仍然会拒绝。也就是说它降低误拒，不放松硬风险。

### 4.4 情绪检测

**Q：情绪检测怎么实现？**  
A：先取人脸 crop，计算嘴部开合、眼部暗线、亮度、对称性等启发式特征；再优先调用 EmotiEffLib ONNX `enet_b0_8_best_vgaf`，输入前 BGR 转 RGB；失败则回退 DeepFace，再失败使用启发式。最后 `_stabilize_emotion()` 对低置信 surprise 做保护，结果写入 `emotion_records` 并在前端统计。

**Q：为什么不是总是 surprise 了？**  
A：低置信 surprise 如果嘴部几何不支持张嘴，会被稳定为 neutral、启发式结果或第二候选，并保留原始模型输出供前端显示。

### 4.5 人脸库

**Q：一个学生多张照片怎么提高准确率？**  
A：`recognize()` 按学生聚合，不是只逐样本抢最高分。最终学生级分数融合最佳单样本、TopK 均值、质量加权质心和支持样本数；多角度高质量样本越多，匹配越稳。

**Q：批量导入文件名格式？**  
A：只支持 `学号-姓名-专业-性别.jpg/png`，例如 `2022302181209-吴悦-网络空间安全-女.jpg`。导入后弹出成功/失败清单。`学号-姓名=专业-性别` 当前不支持。

### 4.6 权限

**Q：前端隐藏按钮是不是不安全？**  
A：隐藏只是体验。真正权限在后端：教师接口 `require_role("teacher")`，学生查询强制按当前 student_id 过滤，`/storage` 也限制学生只能访问自己的样本。

## 5. 现场推荐展示顺序

1. 教师登录，总览系统数据。
2. 考勤页：开启摄像头 → 手动抓拍预检 → 开始活体打卡。
3. 记录页：筛选考勤记录 → 导出 Excel。
4. 学生/人脸库：样本预览/删除 → 批量导入人脸图片 → 展示成功/失败清单。
5. 合照识别：上传 10 人 demo 合照 → 看标注图和名单 → 统计报表。
6. 情绪分析：展示考勤/合照中的 emotion 和统计页情绪分布 → 验收清单情绪诊断。
7. 安全自测：静态照片、移动照片、预录视频、随机挑战抗视频说明。
8. 验收清单：按评分点收尾。

## 6. 当前局限与诚实回答

- 当前人脸检测使用 OpenCV Haar，复杂遮挡、极端侧脸和低清晰度合照不如 RetinaFace/InsightFace。
- 当前人脸特征是本地轻量特征，不是深度人脸模型；但已用多样本聚合和教师确认降低风险。
- 当前活体不是金融级深度活体，但已覆盖课程要求的照片、移动照片、预录视频演示防护。
- 情绪分类是表情分类，不代表真实心理状态；受光照、角度、遮挡影响。
