# 《内容安全实验》课程设计报告（草稿）

## 题目

基于 BS 架构的班级智能考勤系统设计与实现

## 摘要

本系统围绕内容安全场景中的人脸识别、活体检测和面部情绪分析技术，设计并实现了一套班级考勤系统。系统采用 Browser/Server 架构，前端负责摄像头采集、合照上传和结果展示，后端负责活体检测、人脸库匹配、合照批量识别、情绪分析、权限控制和数据导出，数据库负责学生、人脸样本、考勤记录、活动参与频次及情绪记录的持久化存储。

## 1. 需求分析

### 1.1 功能需求

1. 基础考勤：浏览器调用摄像头，采集学生人脸，多帧提交至后端，返回学生姓名、学号、考勤状态、时间、活体结果和情绪结果。
2. 人脸库管理：教师可以新增、删除学生，并为学生上传多张人脸样本。
3. 考勤记录查询：按日期、学号筛选考勤记录，支持 Excel 导出。
4. 合照识别：教师上传班级或活动合照，后端检测多张人脸，匹配人脸库，生成参与学生名单。
5. 活动频次统计：自动记录每位学生参与活动次数，前端以报表展示。
6. 情绪分析：考勤和合照识别过程中同步记录情绪分类结果，并提供统计展示。
7. 权限控制：教师可查看和管理全部数据，学生只能查看本人数据。

### 1.2 性能需求

- 系统应能在普通笔记本上离线运行。
- 单次考勤响应应控制在数秒内。
- 合照识别应支持至少 10 人合照；受 Haar 检测与样本质量影响，演示时应使用较清晰正脸照片。

### 1.3 安全需求

- 防止照片或视频替代真人打卡：采用随机动作挑战、多帧人脸位置变化和纹理质量检测。
- 防止越权访问：后端接口区分教师与学生角色。
- 防止异常输入导致系统崩溃：图片解析失败、摄像头失败、挑战过期、人脸未检出等均返回明确错误。
- 避免隐私泄露：项目不内置真实人脸数据，样本只保存在本地目录。

## 2. 系统设计

### 2.1 架构设计

系统采用三层 BS 架构：

- 表现层：`templates/index.html`、`static/css/app.css`、`static/js/app.js`
- 业务层：`app.py` 中的 Flask API 路由，`core/security.py` 权限控制
- 算法层：`core/vision.py` 实现人脸检测、特征提取、活体检测、情绪分析
- 数据层：SQLite 数据库，由 `core/db.py` 初始化

### 2.4 算法设计

#### 人脸检测

使用 OpenCV Haar Cascade 完成正脸检测，并补充侧脸检测。检测结果经过非极大值抑制，保留高质量人脸框。

#### 人脸特征

对人脸区域进行灰度化、尺寸归一化、直方图均衡，提取 LBP 纹理直方图、分块纹理和低分辨率灰度结构特征，拼接后 L2 归一化。识别阶段采用余弦相似度与人脸库逐一比较。

#### 活体检测

后端从 9 种动作池中生成 3 组随机动作挑战，如向左、向右、向上、向下、靠近、远离、左右摆动、上下点头、远近变化。前端每组最多 5 秒采集多帧并请求单组检测，只有检测到当前动作后才进入下一组；最终后端检测每组人脸中心点、面积变化、帧差、重复帧比例，并结合清晰度、亮度、对比度等质量指标判断是否通过。

#### 情绪分析

当前版本采用离线启发式情绪分类：根据眼部、口部区域的暗区比例、边缘强度、亮度、对称性等指标，将表情分类为 `neutral`、`happy`、`surprise`、`sad`、`angry`。后续可替换为 FER/DeepFace 模型。

## 5. 结果分析

当前系统已完成端到端链路。系统使用老师提供的授权班级照片目录 `face_data` 建立人脸库，并生成导入报告、特征评估报告和演示合照。

### 5.1 老师提供班级照片导入结果

导入命令：

```powershell
python scripts\import_face_data.py --source ..\face_data
python scripts\evaluate_face_data.py
python scripts\make_demo_collage.py
```

当前导入结果：

- 原始图片数：132 张；
- 成功入库人脸样本：130 张；
- 导入成功率：约 98.48%；
- 平均人脸质量分：约 0.616；
- 失败样本：1 张，原因是未检测到清晰人脸；
- 生成 10 人演示合照，结果保存在 `docs/demo_collage_report.json`。
- 系统生成 10 人演示合照并完成合照接口自测，检测到 10 张以上人脸；纯人脸匹配名单与已知生成名单均写入 `docs/group_collage_selftest_report.json`，可用于现场证明“10 人合照上传、检测、标注、名单生成、活动频次记录”的完整流程。

系统将默认人脸匹配阈值设为 `0.70`，兼顾合照召回率与误识别率。基于样本库的两两特征测试结果显示，在阈值 0.80 附近非同人误接收率约为 0.33%；若现场更强调“安全可靠”，可将阈值临时调高到 `0.85` 或 `0.90`。由于当前大多数同学只有 1 张样本，同人正样本对较少，当前识别已按学生聚合多样本得分；若每人补采 3–5 张不同光照/角度照片，可通过最高分、TopK 均值和稳定样本数进一步提升考勤识别鲁棒性。合照识别演示时应优先使用清晰正脸、无遮挡图片。

## 6. 存在问题与改进方案

1. Haar Cascade 对侧脸、遮挡、低清晰度合照不够鲁棒；后续可接入 RetinaFace 或 YOLO 人脸检测。
2. LBP 特征识别效果弱于深度学习模型；后续可接入 InsightFace、FaceNet 或 dlib。
3. 情绪分类目前为启发式模型，适合作为课程演示链路；后续可替换为 FER/DeepFace。
4. 活体检测已加入 9 种动作池、3 组限时挑战；后续还可进一步加入眨眼、张嘴、随机读数字、屏幕反光检测等机制。

本课程设计完成了从需求分析、系统设计、代码实现到测试规划的完整流程，覆盖了人脸识别、活体检测、合照批量识别、情绪分析和权限控制等内容安全实践要点。系统结构清晰、接口可复用、数据模型完整，具备进一步升级算法和扩展部署的基础。
