# 创新点与难点验收清单

本文件用于答辩前逐项验收项目亮点。每一项都给出“怎么演示、看什么结果、对应代码/脚本”。

## 1. 分阶段即时活体判定

**目标：** 证明正式考勤不是一次性拍照提交，而是每组动作实时后端判定，当前组通过才进入下一组。

- 页面验收：`考勤打卡 -> 开启摄像头 -> 开始活体打卡`。
- 观察点：页面显示第 1/3、2/3、3/3 组；每组持续采样并显示“该组动作通过”后才进入下一组。
- 接口证据：前端循环调用 `/api/attendance/liveness-stage`；最后统一调用 `/api/attendance/check` 复核全部帧。
- 代码证据：
  - `static/js/app.js::captureStageUntilPass()`
  - `app.py::attendance_liveness_stage()`
  - `app.py::attendance_check()`
- 脚本验收：

```powershell
python scripts\liveness_stage_selftest.py
```

## 2. 动作随机 + 闪光随机的双随机机制

**目标：** 证明系统同时随机动作序列和随机颜色闪光序列，增加预录视频伪造难度。

- 页面验收：`安全自测 -> 展示随机挑战抗视频`。
- 观察点：显示 10 种动作池、每次抽 3 组、每组 5 秒、90 秒过期、每组 4 段随机颜色。
- 接口证据：`/api/security/challenge-randomness`。
- 代码证据：
  - `app.py::LIVENESS_ACTION_LABELS`
  - `app.py::_random_flash_sequence()`
  - `app.py::attendance_challenge()`
  - `core/vision.py::_flash_response_check()`
- 说明口径：动作顺序随机；颜色序列随机；闪光元数据不一致会拒绝，弱光下闪光响应进入综合评分和软警告。

## 3. 多样本学生级聚合识别

**目标：** 证明识别不是单张样本最高分，而是按学生聚合多张样本，提升稳定性。

- 页面验收：`学生/人脸库 -> 样本` 查看某学生多样本；`考勤打卡 -> 手动抓拍预检` 查看学生聚合分、最佳单样本、样本数、第二名和分差。
- 合照验收：合照结果表显示 `score`、`best_sample_score`、`sample_count`、`score_margin`。
- 代码证据：
  - `core/vision.py::recognize()`
  - 聚合指标：best score、TopK 均值、centroid score、support bonus、第一/第二候选分差。
- 脚本验收：

```powershell
python scripts\face_multisample_selftest.py
```

## 4. 合照识别“自动识别 + 教师确认”闭环

**目标：** 证明系统不是只输出算法结果，而是形成活动参与名单和统计闭环。

- 页面验收：`合照识别 -> 上传合照 -> 查看标注图/候选表 -> 确认参与名单 -> 统计报表`。
- 观察点：自动确认、待确认候选、分数、情绪、标注图；教师确认/补选后写入活动参与表。
- 接口证据：
  - `/api/group/recognize`
  - `/api/group/<activity_id>/participants`
  - `/api/group/stats`
- 代码证据：
  - `app.py::group_recognize()`
  - `app.py::group_confirm_participants()`
  - `core/vision.py::annotate_group_image()`
- 脚本验收：

```powershell
python scripts\group_collage_selftest.py
python scripts\group_collage_50_selftest.py
```

## 6. 人脸库批量导入错误清单

**目标：** 证明老师授权照片可以直接导入，并能明确展示成功/失败文件。

- 页面验收：`学生/人脸库 -> 批量导入人脸图片`。
- 文件名格式：`学号-姓名-专业-性别.jpg/png`，例如 `2022302181209-吴悦-网络空间安全-女.jpg`。
- 观察点：导入后自动弹出成功/失败清单；自动创建/更新学生；新增样本。
- 接口证据：`/api/students/faces/bulk`。
- 代码证据：
  - `core/face_import.py::parse_student_image_filename()`
  - `app.py::bulk_import_student_face_images()`
  - `static/js/app.js::showBulkFaceImportResult()`
- 命令行验收：

```powershell
python scripts\import_face_data.py --source ..\face_data
```

## 7. 安全自测脚本与最终验收脚本

**目标：** 证明项目不是只靠现场演示，而是有可重复的测试证据。

推荐命令：

```powershell
python -m compileall app.py core scripts
node --check static\js\app.js
python scripts\liveness_stage_selftest.py
python scripts\liveness_antispoof_selftest.py
python scripts\group_collage_selftest.py
python scripts\group_collage_50_selftest.py
python scripts\emotion_selftest.py
python scripts\final_acceptance.py
```

关键输出：

- `FINAL ACCEPTANCE OK`
- 10 人合照：`recall=1.0`、`precision=1.0`
- 50 人压力图：检测 50 人、匹配 50 人、`recall=1.0`、`precision=1.0`
- 活体攻击自测：静态/移动照片和预录视频攻击均不能通过。

## 8. 后端强权限和 storage 图片保护

**目标：** 证明权限不是只靠前端隐藏按钮，而是后端强制校验。

- 页面验收：教师账号可管理学生/样本/合照/导出；学生账号只能看本人记录。
- 接口证据：教师接口使用 `@require_role("teacher")`；普通查询使用 `@require_login` 并按 `student_id` 过滤。
- storage 保护：`/storage/<path>` 会校验路径是否在 `storage` 根目录下，并限制学生访问非本人样本图片。
- 代码证据：
  - `core/security.py::require_login()`
  - `core/security.py::require_role()`
  - `app.py::storage()`
  - `app.py::attendance_records()`
  - `app.py::emotion_stats()`
